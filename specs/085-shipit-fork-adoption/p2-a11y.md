### Plan

## Item 28: Radix FocusScope + Escape Dismiss on Non-Modal Drawers

**Source commit:** `e270a012`

### Current State
- Base drawer: `src/presentation/web/components/common/base-drawer/base-drawer.tsx`
  - Uses Radix Dialog primitives
  - `modal={false}` (default non-modal)
  - Manual click-outside handler (lines 71-94)
- **Escape key handling duplicated** across 3+ components:
  - `adopt-branch-drawer.tsx`: `if (e.key === 'Escape')`
  - `floating-action-button.tsx`: manual Escape handler
  - `ModelPicker/index.tsx`: manual Escape handler
- **No explicit FocusScope** - relies on Radix Dialog internal focus management
- **WCAG violations:** 2.4.3 (Focus Order), 2.1.2 (No Keyboard Trap)

### Plan
1. **Centralize Escape handling** in `BaseDrawer`:
   ```tsx
   useEffect(() => {
     if (!open) return;
     const handleEscape = (e: KeyboardEvent) => {
       if (e.key === 'Escape') {
         e.preventDefault();
         onClose();
       }
     };
     document.addEventListener('keydown', handleEscape);
     return () => document.removeEventListener('keydown', handleEscape);
   }, [open, onClose]);
   ```
2. **Add Radix FocusScope** for non-modal drawers:
   ```tsx
   import { FocusScope } from '@radix-ui/react-focus-scope';
   
   <FocusScope trapped={modal} loop>
     <DrawerContent>{children}</DrawerContent>
   </FocusScope>
   ```
3. **Remove duplicate Escape handlers** from individual drawer implementations
4. Verify focus returns to trigger element on close

### Files to Change
- `src/presentation/web/components/common/base-drawer/base-drawer.tsx` (centralize Escape + FocusScope)
- `src/presentation/web/components/common/control-center-drawer/adopt-branch-drawer.tsx` (remove duplicate)
- `src/presentation/web/components/common/floating-action-button/floating-action-button.tsx` (remove duplicate)
- `src/presentation/web/components/features/settings/ModelPicker/index.tsx` (remove duplicate)

### Risk: MEDIUM - affects all drawer interactions; test focus behavior thoroughly
### Impact: MEDIUM - WCAG 2.4.3, 2.1.2 compliance

## Item 29: Route-Change Screen-Reader Announcements + aria-label on Icon Buttons

**Source commit:** part of `6848b7c5`

### Current State
- **Only 1 aria-live region:** `ChatMessageList.tsx` uses `aria-live="polite"`
- **52+ files** use `useRouter`/`usePathname`/`useSearchParams` - no route change announcements
- **No announcement pattern** for page navigation
- **Icon buttons:** likely missing `aria-label` on icon-only buttons (audit needed)

### Plan

#### Route-Change Announcements
1. Create announcement hook:
   ```typescript
   // src/presentation/web/hooks/use-route-announcer.ts
   export function useRouteAnnouncer() {
     const pathname = usePathname();
     const [announcement, setAnnouncement] = useState('');
     
     useEffect(() => {
       const title = document.title || 'Page loaded';
       setAnnouncement(`Navigated to ${title}`);
     }, [pathname]);
     
     return announcement;
   }
   ```
2. Add announcement region to root layout:
   ```tsx
   // src/presentation/web/app/layout.tsx
   <div role="status" aria-live="polite" aria-atomic="true" className="sr-only">
     {announcement}
   </div>
   ```

#### Icon Button aria-labels
3. Audit all icon-only buttons:
   ```bash
   # Search for buttons with only icon children, no text
   grep -r '<Button.*variant.*icon\|<button.*aria-label' src/presentation/web/
   ```
4. Add `aria-label` to each icon-only button:
   ```tsx
   <Button variant="ghost" size="icon" aria-label="Close drawer">
     <X className="h-4 w-4" />
   </Button>
   ```

### Files to Change
- **New:** `src/presentation/web/hooks/use-route-announcer.ts`
- `src/presentation/web/app/layout.tsx` (add announcement region)
- Multiple component files (add aria-label to icon buttons)

### Risk: LOW - additive accessibility enhancements
### Impact: HIGH - fundamental screen reader usability for SPA navigation
